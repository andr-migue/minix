\section{Introducción}
Este proyecto se desarrolló en el contexto de la asignatura Sistemas Operativos con el objetivo de estudiar, desde la práctica, principios de concurrencia, planificación y sistema de archivos sobre una base real: MINIX. A diferencia de ejercicios aislados, la metodología usada exige intervenir código productivo del sistema, recompilar, validar y documentar resultados.

Los objetivos generales fueron: (1) preparar el entorno de trabajo en MINIX, (2) realizar una modificación visible del sistema (\texttt{/etc/motd}), (3) depurar un bug real en la capa de compatibilidad \texttt{pthread\_*}, (4) implementar un comando de usuario (\texttt{tree}) y (5) extender el scheduler para distinguir procesos CPU-bound y aplicar penalización gradual.

Este informe documenta específicamente el estado actual del repositorio \texttt{minix} y los cambios efectivamente registrados en Git, trazándolos contra el \emph{Cronograma de hitos} entregado en \texttt{orientation/Cronograma de hitos.pdf}.

\subsection{Depuración de un bug en \texttt{pthread}}
\textbf{Síntoma esperado según orientación:} bloqueo en la segunda llamada a \texttt{pthread\_mutex\_trylock}.

\textbf{Análisis:} la capa \texttt{pthread\_*} en MINIX delega en \texttt{mthread\_*}. En \texttt{minix/lib/libmthread/pthread\_compat.c}, la implementación de \texttt{pthread\_mutex\_trylock} llamaba recursivamente a sí misma, provocando fallo lógico severo.

\textbf{Corrección aplicada (mínima):}
\begin{lstlisting}[style=cstyle,caption={Diff funcional del fix de pthread}]
- return pthread_mutex_trylock(mutex);
+ return mthread_mutex_trylock(mutex);
\end{lstlisting}

El cambio quedó registrado en el commit \texttt{67eeae1b7}. Esta corrección concuerda con el Hito 2 y con la relación requerida \texttt{pthread\_*} (compatibilidad) $\rightarrow$ \texttt{mthread\_*} (implementación real).

\subsection{Implementación del comando \texttt{tree}}
La implementación se integró como comando de usuario mediante:
\begin{itemize}[leftmargin=*]
\item alta de \texttt{bin/tree/tree.c},
\item alta de \texttt{bin/tree/Makefile},
\item inclusión de \texttt{tree} en \texttt{bin/Makefile}.
\end{itemize}

\textbf{Diseño del algoritmo:} recursivo explícito (\texttt{print\_tree(path, depth)}), adecuado por simplicidad y correspondencia directa entre nivel de recursión e indentación visual.

\textbf{Llamadas al sistema usadas:}
\begin{itemize}[leftmargin=*]
\item \texttt{opendir}/\texttt{readdir}/\texttt{closedir} para iteración de directorios.
\item \texttt{lstat} para obtener metadatos sin seguir enlaces simbólicos.
\end{itemize}

\textbf{Prevención de ciclos:} el código evita descender por symlinks mediante \texttt{!S\_ISLNK(entry\_stats.st\_mode)}, cumpliendo el requisito obligatorio de la guía.

\begin{lstlisting}[style=cstyle,caption={Fragmento clave de \texttt{bin/tree/tree.c}}]
int check = lstat(fullpath, &entry_stats);
if (!(check == -1) && S_ISDIR(entry_stats.st_mode) &&
    !S_ISLNK(entry_stats.st_mode)) {
    print_tree(fullpath, depth + 1);
}
\end{lstlisting}

\subsection{Penalización por uso intensivo de CPU}
\textbf{Análisis previo y puntos intervenidos:}
\begin{itemize}[leftmargin=*]
\item Agotamiento de quantum: \texttt{do\_noquantum()} en \texttt{schedule.c}.
\item Balance periódico: \texttt{balance\_queues()}.
\item Estado por proceso: \texttt{struct schedproc} en \texttt{schedproc.h}.
\end{itemize}

\textbf{Diseño implementado:}
\begin{itemize}[leftmargin=*]
\item Ventana temporal ya existente del balanceador (\texttt{BALANCE\_TIMEOUT = 5s}).
\item Umbral CPU-bound: \texttt{CPU\_BOUND\_QUANTUM\_THRESHOLD = 3}.
\item Penalización máxima: \texttt{MAX\_PENALTY\_LEVEL = 2}.
\end{itemize}

\textbf{Cambios de datos por proceso:}
\begin{lstlisting}[style=cstyle,caption={Campos añadidos en \texttt{schedproc.h}}]
unsigned base_priority;
unsigned quantum_count;
unsigned penalty_level;
\end{lstlisting}

\textbf{Cambios de lógica:}
\begin{itemize}[leftmargin=*]
\item \texttt{do\_noquantum()} incrementa \texttt{quantum\_count} para procesos no de sistema.
\item \texttt{do\_start\_scheduling()} inicializa \texttt{base\_priority}, \texttt{quantum\_count} y \texttt{penalty\_level}.
\item \texttt{balance\_queues()} aplica penalización si \texttt{quantum\_count >= 3}, recuperación gradual si \texttt{quantum\_count == 0}, y reinicia contador por ventana.
\end{itemize}

La modificación corresponde al Hito 3 y materializa la política solicitada en \texttt{Orientación del proyecto.pdf}.

\section{Resultados globales y discusión}
Desde la perspectiva del repositorio, los tres hitos del cronograma están cubiertos por cambios concretos, versionados y trazables. El Hito 1 queda evidenciado por la personalización de \texttt{motd}; el Hito 2 por la implementación/integración de \texttt{tree} y la corrección de \texttt{pthread\_mutex\_trylock}; y el Hito 3 por la extensión del scheduler con política de penalización CPU-bound por ventanas.

La principal limitación metodológica de este análisis es que se basa en evidencia estática de código y commits (no en ejecución dentro de la VM MINIX en este entorno). Por ello, el cierre formal del informe académico debe incluir anexos de ejecución (salidas del programa de prueba pthread, pruebas de \texttt{tree} en \texttt{.}, \texttt{/usr}, \texttt{../}, y evolución de prioridad en escenarios CPU-bound vs interactivo).
